Wizard research: how to build the AI toolkit installer

2026-11-05 · for approval · nothing installed in your real setup, nothing in this repo changed except this report · reply with the numbers, e.g. "1-4 yes, 6 change X"

Summary. Build it yourself in Go, as one static binary with the engine as a library and thin front ends: a DOS-style console UI on tview/tcell now, a --plain line mode for screen readers and CI, and later a Windows GUI that drives the same engine through a JSON plan. Nothing I found combines a machine scan, a questionnaire and a safe merge; the closest tools (vercel skills, rulesync, ruler, claude-code-templates) all need Node and only cover parts. The engine works as scan → answers → rules → plan → diff → apply with backup and ownership manifest; only the answers are saved. Ship through GitHub Releases with checksums, build attestations and an SBOM; sign later through SignPath Foundation, because Azure Artifact Signing isn't open to individuals in Germany.

The earlier draft (docs/wizard-design.md, which I read only after writing my own answer) made the same core choice: Go, tcell, one binary, hooks as subcommands. Section 10 lists eight changes I'd make to it. The most important: the Windows path of Codex requirements.toml is now confirmed; the scan should read the Claude Code registry policy too; and the draft's network-reachability check contradicts "no network calls". The biggest finding came from Codex's review, which I then verified: a Claude Code hook that fails to start lets the tool call through by default. So if company policy blocks agtk.exe, the git guard switches off without a sound. Hooks must be written with "onFailure": "block" (Claude Code v2.1.295+), and the binary must be test-run from its install folder before hooks point at it. This also contradicts the add-ons report's "fails closed" note for today's Node hook.

Prototypes. I built the same setup screen in Go/tview, Rust/ratatui and .NET/Terminal.Gui. I ran each in the old console host (conhost) and in WSL Ubuntu (tmux), with key presses, resizing, TERM=linux and LANG=C. Windows Terminal screenshots are missing: my first attempt grabbed your screen while a game was running. I deleted those captures and switched to headless captures (section 2).

Models used (AGENTS.md table, FrontierCode 1.1 reading of 2026-11-04): main session Opus at medium; six searching and reading agents on Haiku at medium ("finding where things live" row). The scout agent has no web tools, so these were general-purpose agents pinned to Haiku/medium. One fact-check page reader, no Opus fan-out. Codex second opinion on --profile deep (GPT-6 Astra, max).

Recommendations

1 · Prior art: build your own, borrow ideas YES

ChoiceWrite the wizard yourself. Borrow three ideas: claude-code-templates' interactive catalog flow, rulesync/ruler's map of "one source → many agent file locations", and the vercel skills CLI's per-agent skill folder table (for when more agents are added).
Why not fork
  • vercel-labs/skills (38.1k★, v1.7.6 2026-11-03, MIT, TypeScript): installs skills into 75+ agents. Skills only, no AGENTS.md, hooks or settings, and it needs Node.
  • rulesync (1.6k★, v43.6.0 2026-11-03, MIT, Node): generates rules, MCP, commands, subagents and skills for many tools from one source. No scan, no questions. I couldn't read whether it merges or overwrites.
  • ruler (3.0k★, v0.3.46 2026-10-22, MIT, Node): centralises instructions and MCP config. Same gaps.
  • claude-code-templates (33.1k★, v1.29.7 2026-10-09, MIT, Node): the closest UX, an interactive browser and installer, but Claude Code only, with no scan or merge guarantees.
  • Found by Codex: AgentDeck (2★, v1.0.0 2026-10-06, MIT, JS) is a local GUI with agent detection, presets, diff preview, managed blocks and undo for 20+ agents; by its own account only Claude Code was tested live. ai-agent-rules (10★, v0.81.2 2026-11-01, MIT, Python) has an interactive wizard, profiles and a merge pipeline. Both are small and unproven, but worth reading for their merge code before writing yours. Neither handles corporate policy.
  • openskills (10.8k★): last release 2026-01-17, stale. smithery CLI: AGPL. mcp-installer: stale since 2024.
  • chezmoi (22.2k★, v2.74.0 2026-11-01): a strong dotfile engine, but its model is "your files, your templates", not a curated catalog with reasons. winget configure is Windows-only (DSC YAML), so it can't be the output format.
  • Neither Anthropic nor OpenAI has a setup wizard. The official pieces are building blocks: Claude Code plugin marketplaces, claude mcp add, managed settings, Codex requirements.toml.
EvidenceGitHub API, read 2026-11-04: vercel-labs/skills, rulesync, ruler, claude-code-templates, chezmoi, winget configure (2026-07-19). HN 2026-10-22: malicious AGENTS.md files dropped into Downloads (4 points), one more reason never to overwrite instruction files blindly. HN 2026-09-17: 69% of 216 public skills don't trigger reliably (3 points), which supports a small, tested catalog.
RisksYou maintain the per-agent path knowledge yourself. For two agents, that is small.

Alternatives
  • Rust + ratatui: the runner-up. Smallest and fastest, ratatui is active (23.2k★, last push 2026-11-03), and BorderType::Double is built in. Against it: radio, checkbox and focus widgets are yours to write; the Windows toolchain (MSVC licence or a MinGW workaround) is friction for one person; crossterm needs your own TERM and locale detection. Choose it if binary size or startup matters more to you than speed of writing.
  • .NET + Terminal.Gui v2 (11.3k★, v2.5.0 2026-09-11): the most widgets out of the box, and the best Windows GUI path (WinForms/WPF/Avalonia in the same language). But: 2–4 s start, a 13 MB file, and NativeAOT needs MSVC on Windows. Its default look is a modern TUI (◉ ☑ title tabs), so the DOS look needs re-theming.
  • Bubble Tea v2 (Go, 45.6k★, v2.1.1 2026-10-28): Elm-style, very active, but no ready radio/checkbox/frame widgets for this look. tview is the shorter path. Fine to revisit if tview stalls.

The first conhost frame in Go took about 0.2 s longer than Rust; still fine for a wizard.

3 · Machine scan without admin rights YES

ChoicePure Go, no cgo. The result is a typed struct in memory with coarse values; it is never written.
HardwareCPU and RAM: gopsutil v4 (cgo-free) or /proc/cpuinfo//proc/meminfo and GlobalMemoryStatusEx directly. GPU on Windows: DXGI (DedicatedVideoMemory is 64-bit) or the display-class registry value HardwareInformation.qwMemorySize. Not WMI Win32_VideoController.AdapterRAM: it is a uint32, so 8 GB cards read as 4 GB or less (MS Learn, 2023-11-09; DXGI_ADAPTER_DESC1, 2024-02-22). Linux: /sys/class/drm/card*/device/vendor and mem_info_vram_total (AMD), nvidia-smi if present. Store buckets ("8 GB VRAM class"), not models.
ToolsLook each one up on PATH (claude, codex, node, git, uv, python, java, mvn, gradle, go, docker, gh). Skip the WindowsApps\python.exe Store stub; your add-on research hit it with pyright. Run --version only with a 2 s timeout and no shell. A tool found in the current folder ahead of PATH is a hijack risk, so resolve absolute paths first.
Claude Code policiesFiles: C:\Program Files\ClaudeCode\managed-settings.json + managed-settings.d\ + managed-mcp.json; Linux /etc/claude-code/…. Registry: HKLM\SOFTWARE\Policies\ClaudeCode, value Settings (JSON), and the same path under HKCU as the lowest managed source. The legacy C:\ProgramData\ClaudeCode is no longer read. Keys that change what the wizard may do: allowManagedHooksOnly, strictKnownMarketplaces, allowManagedMcpServersOnly, allowManagedPermissionRulesOnly (all managed-only), plus disableAllHooks, forceLoginMethod, apiKeyHelper. Sources: managed settings, settings reference, read 2026-11-05.
Codex policiesrequirements.toml: /etc/codex/requirements.toml and %ProgramData%\OpenAI\Codex\requirements.toml (confirmed verbatim). Relevant keys: top-level allow_managed_hooks_only (not inside [hooks]; Codex corrected me, then I verified it), [features] plugins = false, [marketplaces] restrict_to_allowed_sources, mcp_servers (an empty table disables all MCP), [rules]. Cloud and macOS-MDM requirements can't be read locally. So the scan reports each capability as allowed / blocked / unknown, together with where that came from, and "unknown" never counts as allowed. One nuance: Claude Code's allowManagedMcpServersOnly restricts which allowlists count; it doesn't ban user MCP servers outright. managed_config.toml paths are unconfirmed. Source: managed configuration, read 2026-11-05.
Gateways and proxiesRecord only whether these are set: ANTHROPIC_BASE_URL, ANTHROPIC_BEDROCK_BASE_URL/VERTEX, CLAUDE_CODE_USE_*, OPENAI_BASE_URL, Codex model_providers, HTTP(S)_PROXY, NODE_EXTRA_CA_CERTS, the WinINet ProxyServer/AutoConfigURL values under HKCU. Never the values: URLs can hold credentials. If the user picks "gateway", ask for model names instead of probing.
Never collectUsernames, hostnames, domain names, full paths (they contain the username), environment variable values, tokens or API keys from settings files, proxy URLs, serial numbers, MAC addresses, GPU or CPU serials. Read config files for key presence. This follows GDPR Art. 5(1)(c) data minimisation (text).
Not checkedWhether a standard user can read AppLocker/App Control policy (Get-AppLockerPolicy -Effective, SrpV2 registry) and dsregcmd /status. A more reliable test is empirical: copy the binary to its install folder and run agtk version from there (item 5).

4 · Catalog and recommendation rules YES

ChoiceOne YAML file per item, embedded with go:embed, checked against a JSON Schema in CI (santhosh-tekuri/jsonschema v6.0.3, 2026-08-06). Rules are structured YAML conditions, not a text language: all: / any: / not: over {fact, op, value}. That needs no parser and no precedence or escaping rules, and the evaluator still returns a trace per clause, so F1 can show "recommended because: stacks contains java ✓, tool codex ✓" from the actual evaluation. (Changed after Codex's review; my first answer was a small text language like the draft's.) Define missing values explicitly: with use unknown, use != personal must be unknown, not true. Each item also carries supported client versions, dependencies, conflicts, its pinned source and its install scope.
Alternativesexpr-lang/expr (8.1k★, v1.17.8): mature and side-effect-free, but no clause trace and more syntax than needed. cel-go: the standard, but a heavy dependency for a dozen rules. JSONLogic: unreadable in YAML. OPA/Rego: far too heavy. Plain Go code per item: fastest to write, but contributors then need Go to add an item.
Context costPer item, store the always-loaded text: AGENTS.md modules (every session), skill description + when_to_use (listed every turn, capped at 1,536 characters each), and subagent descriptions. MCP tools cost about 0 in Claude Code because tool search defers all of them by default (MCP docs, read 2026-11-05). In the wizard, use chars/4. In CI, use the free count_tokens endpoint against the target model: Opus 4.7+ models tokenize about 30% heavier (token counting). Codex caps project docs at 32 KiB (project_doc_max_bytes).
RisksA home-made language grows. Keep it to and/or/not, ==, !=, >=, contains and version comparison, and fail CI on unknown fact names.

5 · Writing config safely YES

Choiceplan → diff → apply. The plan is a list of file operations, shown as a diff on the summary screen and available as --json.
  • Ownership manifest (~/.agtk/state.json): every key, block or file agtk wrote, with the hash and the previous value of what it wrote. Re-runs do a three-way comparison (what agtk wrote last, what is there now, what it wants now). Items the user changed by hand become explicit conflicts on the summary screen, never silent overwrites. Undo must keep changes the user made after the apply.
  • Markdown: managed blocks between <!-- agtk:begin id --> markers, the same idea as Ansible blockinfile.
  • JSON (settings.json, hooks.json): patch only owned keys, keeping order and comments. tailscale/hujson gives a comment-preserving tree; test its round-trip first.
  • TOML (config.toml): creachadair/tomledit keeps order and comments. pelletier/go-toml v2 and BurntSushi/toml lose formatting.
  • Writes: temp file in the same folder, then replace. Go's os.Rename does not promise atomic replacement on Windows, so use ReplaceFile/MoveFileEx there and test it. Keep permissions; handle symlinks and junctions deliberately; protect the backups (they may contain secrets from existing files). Keep a journal, so a run interrupted halfway through several files can be finished or rolled back. A timestamped backup per run, and agtk undo.
  • Concurrency: Claude Code itself rewrites ~/.claude.json, and concurrent writes have corrupted it (#29004, closed as a duplicate 2026-02-26). A lock only stops a second agtk, and a re-check still leaves a race. So for v0.1: ask the user to close Claude Code and Codex before writing shared files, and prefer claude mcp add over editing ~/.claude.json directly. An imported plan (apply --plan) is validated against allowed operations and target folders, and policy and file state are re-checked at apply time.
  • Hooks without Node: the hooks are subcommands of the same binary (agtk hook git-guard). A hook that can't start, times out or exits with an error lets the Claude Code tool call proceed by default. Only "onFailure": "block" (Claude Code v2.1.295+) makes it fail closed (hooks docs, verified 2026-11-05). So: write onFailure: "block" and gate on the Claude Code version. Copy the binary to its install folder and run it from there before registering hooks. If it can't run (App Control/AppLocker), fall back to tier B (permission rules) and say so. Test a denied launch, a missing binary and a timeout.
TestingGolden files under testdata/ with an -update flag. testscript (v1.15.0) for end-to-end CLI runs with a fake $HOME. Property test: apply twice changes nothing; apply then undo restores the bytes. CI on windows-latest and ubuntu-latest; Docker for other distros (Fedora, Alpine/musl); WSL locally. Windows Sandbox is not available on Windows 11 Home.
RisksFormats you don't own change, for example Codex hook trust hashes and Claude Code's settings schema. Pin the agent versions in the catalog (supports: claude >= 2.1.x) and let agtk status warn on drift.

6 · Distribution and trust YES

v0.1
  • GoReleaser in GitHub Actions on a tag: zip (Windows) and tar.gz (Linux) for x64 and arm64.
  • SHA256SUMS, an SBOM, actions/attest-build-provenance, and immutable releases (GA 2025-10-28). Users can check with gh attestation verify or gh release verify-asset.
  • Build with -trimpath and govulncheck in CI.
  • The README explains SmartScreen's "More info → Run anyway" honestly.
  • No curl | sh and no irm | iex: a download link plus a checksum line per OS. The offline zip is the corporate path.
  • Self-update: notify only (agtk status says a new version exists).
Signing
  • Azure Artifact Signing (formerly Trusted Signing): individual validation is US and Canada only. Organisations in the EU qualify, so only with a registered business. About $9.99/month (quickstart, 2026-10-08).
  • EV certificates no longer skip SmartScreen. Microsoft says buying EV for that alone is no longer justified; reputation builds per file hash and per certificate (SmartScreen reputation, 2026-08-17).
  • SignPath Foundation: free for OSS that is released, maintained, OSI-licensed, built automatically and documented. The certificate names SignPath Foundation, not you (terms). Apply after v0.x has real releases.
  • cosign or Sigstore proves the build origin but does nothing for Windows trust. The attestations above cover the same need.
Channelswinget validation does not require signing, but it rejects redirecting URLs, and AV flags on unsigned Go binaries are a real risk (winget repository, 2026-07-14). So winget and an own Scoop bucket come after signing. Linux: deb/rpm via nfpm and a Homebrew tap only if people ask. Skip go install as the main route (it builds from source, so there is no checksum of the binary), and skip npm wrappers (a second supply chain).
CorporateApp Control for Business is Microsoft's security feature; AppLocker gets no new features (overview, 2026-03-29). Unsigned binaries in user-writable folders are the first thing such policies block. Smart App Control also blocks unknown unsigned code on clean Windows 11 installs, but it is switched off on managed devices (App Control, 2026-08-18). The PowerShell fallback is weaker than it looks: App Control also puts scripts into Constrained Language Mode, and a script can't unblock a blocked exe. Add an "export for IT" output instead: a managed-settings snippet, a Codex requirements.toml fragment and the file list, which an admin can deploy to a protected folder. Signing alone doesn't grant corporate permission either. An allow rule for agtk also allows its installer subcommands, so a separate minimal hook-runner binary may be easier for IT to approve (Codex's suggestion; consider for v1.0).
RisksWithout signing, a share of corporate users can't run it at all. Practitioner reports on signing from the last 60 days: none found (HN had nothing on-topic; the Reddit archive refused queries without a subreddit).

8 · Old-school UX done right YES

KeysEnter = continue/confirm, Space = toggle, arrows = move, Tab/Shift-Tab = next/previous field, Esc = back, F3 = exit (confirm first; MS-DOS 6 asked twice), F1 = help, which here also means "why this item". Hotkey letters in lists, whiptail-style. Sources: whiptail(1), Debian installer, InstallShield navigation.
FlowWelcome → scan result → questions → recommendations → summary with the file diff → progress → done with "what's left for you" (e.g. "open Codex, run /hooks"). Cancel is possible everywhere except during the write; InstallShield's rule of no Cancel on the final page applies.

Agree (the draft already has it, often better than my own first answer):

  • Go, one static binary per OS and arch, tcell, no runtime on the target.
  • Hooks as subcommands of the binary. This removes the Node dependency and was not in my answer.
  • The six-step flow with a summary of changed files, backup, undo and status.

Differ, and what to change:

  1. Codex requirements.toml on Windows: the draft skips it as unconfirmed. It is confirmed as %ProgramData%\OpenAI\Codex\requirements.toml. Add it, and read [hooks] allow_managed_hooks_only, features.plugins, [marketplaces] and mcp_servers.

  4. Blocked binary means no guard. The draft doesn't test whether agtk.exe can run from ~/.agtk before writing hooks that call it. A hook that can't start lets the call through by default. Add the run probe to the tier decision, write "onFailure": "block", and add an "export for IT" output next to the PowerShell fallback. The same check applies to today's Node-based install: if node goes missing, the git guard is probably off, not fail-closed as the add-ons report says. I did not test this live.
  5. ASCII fallback is promised, but tcell won't do it for double lines (prototype: ?). Implement detection (UTF-8 locale or codepage 65001), --ascii, and single lines on TERM=linux. Also add a "too small" screen.
  6. Accessibility and CI: add --plain and --answers. The draft has apply --profile, which covers re-runs but not a first run without the TUI.
  7. Rules as structured YAML, "why" from evaluation: the catalog already uses a text language (stacks contains python and node, use != personal and not allow_external_mcp). The draft's GUI note "Fyne or a native Windows shell": I'd add "or any shell over plan --json" to keep the choice open.
